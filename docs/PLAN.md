# LuciControl 方案

2026-09-30 · 第二版 · 第 9 节的决定已经拍板，只剩暂停入口和设计稿补的目录入口

LuciControl 是装在 Mac 上的菜单栏 App，让手机上的 Luci Run 能看到并操作这台 Mac 上的 Codex 会话：
决定哪些目录、哪些会话对手机可见，显示会话状态，完成配对、设备管理和更新。它不在 Mac 上重做聊天界面。

**定位（第二版确定）：LuciControl 就是 lucirund。** 用户只装这一个 App，不碰命令行。App 开着才有共享，
退出 App，共享全部关闭。第一版里「lucirund 是独立的系统服务，App 是它的遥控器」的做法作废。

- 设计稿：`design/LuciControl.dc.html`，第 9 轮面板（9a 浅色、9b 深色）和第 14 轮图标（14b）。
- 渲染图：`design/reference/`，`python3 design/tools/render.py` 可以重新生成。
- 对照的代码：`../lucirund`（提交 `8a44384`）、`../yptd-mobile-app` 的 `Sources/RemoteWire`、`../yptd-serve`。

## 0. 结论

1. **这个定位可行，而且比第一版简单。** lucirund 作为 App 的子进程运行：App 启动时拉起，App 退出时结束。
   不装系统服务，不需要命令行，也不需要本机 socket。
2. **原生 Swift 可行，也是推荐的选择。** 画面用 SwiftUI，外壳（菜单栏图标、浮动面板、拖放）用 AppKit，
   最低 macOS 14。设计稿里没有原生做不了的东西。
3. **lucirund 的 Go 代码原样保留**，不用 Swift 重写，也不编进 App 进程。它和手机之间的协议、中继、服务端都不变，
   已发布的手机 App 不用改。
4. **设计稿有四处必须按实际改**：Agent 标签（保留 Codex 和 Claude Code）、配对、设备页、会话级开关。
   另外要补设计稿没画的三页：检查 Codex、配对确认、退出确认。逐项见第 3 节。
5. **lucirund 要加 9 项能力**（5.3 节）。
6. **有一件事要先验证**：不用命令行的人用的是 Codex 桌面版，桌面版和 lucirund 是两个进程，
   同一个会话同一时刻只能由一边操作（第 8 节第 1 条）。它决定产品对这类用户能承诺什么。
7. 第 9 节记录了你的决定，还有两件没定：暂停入口，以及设计稿要补的「停止共享目录」入口。

## 2. 现状：lucirund 今天能做什么

| 项 | 今天的情况 | 出处 |
|---|---|---|
| Agent | 只有 Codex。装了 Codex CLI 就挂到它的共享守护进程，否则自己起一个 app-server | `internal/daemon/config.go` `DefaultAgent` |
| 共享粒度 | 目录（含子目录）。目录下的线程对主人的手机全部可见 | `Config.Visible` |
| 总开关 | `enabled` 和 `until`。关掉时中继连接和 agent 连接一起停 | `service.go` `reconcile` |
| 线程列表 | 最近 100 条；状态 idle / active / notLoaded / error，外加 waiting、running。只有手机连着时才每 15 秒刷新 | `agent.go` |
| 审批 | 只知道 lucirund 自己恢复过的线程上的请求，可以回答 | `agent.go` `onServerRequest` |
| 设备 | 中继给的名单：主人名下的手机，加上被共享用户的手机，带在线状态。没有按设备的开关 | `service.go` `updateViewers` |
| 配对 | Mac 出码（6 位 Crockford 字符，5 分钟过期），已登录的手机认领，Mac 上确认。配的是「这台 Mac 和一个账号」 | `cmd/lucirund/pair.go`，`docs/wire.md` §1a |
| 连接 | 只经中继，端到端加密。不监听任何端口，没有局域网直连 | `README.md` |
| 本机接口 | 没有。命令行靠读写 `config.json`、读 `state.json` | `cmd/lucirund/main.go` |
| 安装 | `~/.local/bin/lucirund`，LaunchAgent `com.his1devil.lucirund` | `install_darwin.go` |
| 更新 | 没有，靠重跑安装脚本 | `scripts/install.sh` |

这台 Mac 现在的状态：lucirund 0.1.0，机器名 fatMac，账号 xiaolu，远程开着，共享了 2 个目录，中继在线，
Codex 0.159.0（共享守护进程模式），令牌 2026-10-28 到期、会自动续期。钥匙串里有 Developer ID Application 证书。

## 4. 技术栈

### 4.1 为什么用原生 Swift

- 要用到的系统能力全是原生接口：菜单栏图标、浮动面板和毛玻璃、开机启动、选择文件夹、拖放、生成二维码、
  启动和看管子进程、签名公证、Sparkle。
- 手机端的 `RemoteWire` 包只依赖 Foundation、CryptoKit、Network，`Package.swift` 已经声明支持 macOS 14。
  线程摘要、机器状态、共享目录、配对码格式这些模型可以直接用，协议改动时两端一起改。
- 常驻菜单栏的程序不该带一整个浏览器内核。
- 这台 Mac 上有 Developer ID 证书，签名和公证能做。

### 4.2 备选方案

| 方案 | 不选的原因 |
|---|---|
| Electron | 要带 Chromium；毛玻璃、拖到菜单栏图标都得另写原生模块 |
| Tauri | 体积小，但同样要原生插件，也用不了 RemoteWire |
| 纯 SwiftUI 的 `MenuBarExtra` | 最省事，但图标收不了拖放，面板的圆角、材质和高度动画不好控制 |
| 把 lucirund 编进 App 进程（Go 的 c-archive） | 少一个进程，但 Go 那边出错会带着界面一起崩，构建也更复杂。用户感觉不到区别 |
| 用 Swift 重写 lucirund | 时间线、日志、图片、app-server 客户端都要再写一遍，之后还要和 Linux、Windows 上的 Go 版保持一致 |

### 4.3 选型

| 项 | 选择 |
|---|---|
| 语言 | Swift 6 |
| 界面 | SwiftUI（`@Observable`）加 AppKit 外壳：`NSStatusItem`、`NSPanel`、`NSVisualEffectView` |
| 最低系统 | macOS 14 |
| 工程 | XcodeGen（`project.yml`，和手机端一样），逻辑放在 SwiftPM 包 `LuciControlCore` 里，可以单测 |
| 依赖 | RemoteWire（路径依赖 `../yptd-mobile-app`）、Sparkle 2 |
| lucirund | Go，代码不变。打成 arm64 加 x86_64 的通用二进制（约 20 MB）放进 App 包，作为 App 的子进程运行 |
| App 和 lucirund 之间 | 子进程的标准输入输出，一行一条 JSON |
| 分发 | Developer ID 签名加公证，zip 或 DMG。要关沙盒，所以不上 Mac App Store |
| 更新 | Sparkle 2，appcast 和安装包放中继的静态目录 `/dist/` |
| Bundle ID | `com.his1devil.lucicontrol` |

## 5. 架构

```
LuciControl.app
 ┌──────────────────────┐
 │ LuciControl（Swift） │  菜单栏图标和面板
 └──────────┬───────────┘
            │ 标准输入输出，一行一条 JSON
 ┌──────────▼───────────┐  WSS · 密文   ┌────────┐     ┌──────────┐
 │ lucirund（Go 子进程）│ ────────────▶ │  中继  │ ──▶ │ Luci Run │
 │                      │ ◀──────────── │ (ECS)  │ ◀── │  (手机)  │
 └──────────┬───────────┘               └────────┘     └──────────┘
            │ JSON-RPC
 ┌──────────▼───────────┐
 │  Codex app-server    │  装了 Codex CLI：挂到它的共享守护进程
 └──────────────────────┘  只有桌面版：用桌面版自带的 codex 起一个
```

### 5.1 生命周期

| 事件 | 结果 |
|---|---|
| App 启动 | 拉起 lucirund。已配对、上次没暂停，就自动恢复共享 |
| 点「暂停」 | lucirund 还在，只断开中继。面板照常显示会话 |
| App 退出 | 通知手机、断开中继、停掉自己起的 app-server，lucirund 退出 |
| App 崩溃或被强制结束 | 管道断开，lucirund 发现后按退出处理 |
| lucirund 崩溃 | App 重新拉起它，间隔从 1 秒起翻倍，最多 30 秒 |
| Mac 睡眠 | 手机看到离线。唤醒后自动重连（已有） |
| 更新后重启 | 共享中断几秒，手机自动重连（已有） |

两点说明：

- 在 Codex CLI 的共享守护进程里跑着的回合，不会因为 App 退出而停下：那是 Codex 自己的进程，终端里的人还在用。
  退出之后手机看不到它，也答不了它的审批。
- 身份、配置、日志仍放在 `~/Library/Application Support/lucirund/`。用户看不到这个名字，已有的安装可以原样接过来。

### 5.2 控制通道

- `lucirund run --stdio`：控制消息走标准输入输出，日志写文件。标准输入一关闭，lucirund 就按正常退出收尾。
- 格式：一行一条 JSON，单条不超过 4 MB。
- App 在 lucirund 里是一个「本机 viewer」：身份是主人，已验证，发送走管道，不加密，不经中继。
  `handleRPC` 里现有的方法原样可用，只有可见性检查对它放行（它就是坐在电脑前的主人）。

### 5.5 和命令行版的关系

- 在 Mac 上装了 LuciControl 就不需要命令行版。命令行版继续给 Linux、Windows 和没有图形界面的机器用，两边是同一份 Go 代码。
- **接管**：这台 Mac 和已经用安装脚本装过的人，机器上有 LaunchAgent `com.his1devil.lucirund`。
  LuciControl 发现后问一次，同意就停掉并删除这个 LaunchAgent。身份、配置、日志都不动，不用重新配对。
  `~/.local/bin/lucirund` 这个文件不删。
- 两边同时运行会被单实例锁挡住，不会出现两个 lucirund 互相顶掉中继连接。

## 6. 几处实现要点

- **面板**：`NSPanel`，无边框、不抢焦点但能成为 key window（路径输入框要用）。贴在菜单栏图标下方，右边不超出屏幕。
  点面板外、按 Esc、切到别的 App 时收起。页面之间是面板内的切换，高度跟着内容动。
- **菜单栏图标**：用带绘制回调的 `NSImage`，在回调里按当前外观取前景色画图形，再画彩色圆点。
  直接用模板图片的话圆点也会被染成单色。未共享时整体 40% 不透明度。
- **右键菜单**：打开面板、暂停 / 恢复共享、设置、退出。
- **退出**：先发 `shutdown`，最多等 2 秒让 lucirund 通知手机，然后结束子进程。
- **开机时启动和崩溃后重启**：用 `SMAppService.agent` 登记一个指向 App 本身的 LaunchAgent，`KeepAlive` 设成只在异常退出时重启：
  正常退出不会被拉起来（退出就是关闭），崩溃了系统会重新打开它。首次使用时默认勾上。这个做法要在阶段 0 验证。
- **系统授权框**：桌面、文稿、下载这些受保护的目录，第一次被 Codex 访问时系统会弹授权框，预计挂在 LuciControl 名下。
  添加这类目录时 App 先读一次目录，让授权框在人还坐在电脑前时弹出来。
- **拖文件夹到图标**：在状态栏按钮上盖一层接收 `.fileURL` 拖放的透明视图，点击照常传给按钮。
- **会话行的排序**：等待审批、运行中、其余按最近更新时间。
- **Mac 上关掉的会话，手机改不回来**：手机只能改共享目录，碰不到会话级设置。
- **演示模式**：`--demo` 用设计稿的示例数据，`--window` 把面板放进普通窗口，方便截图和设计稿逐页对比。

## 8. 风险和边界

1. **桌面版和手机不能同时操作同一个会话。** 这是新定位下最要紧的一条，因为不用命令行的人用的是 Codex 桌面版。
   你定的：桌面版的支持放到最后做（第 7 节阶段 6）。2026-09-30 用 `lucirund/cmd/lock-probe`（起一个桌面版自带的 codex 0.158.0-alpha.2.1 做 app-server，和 lucirund 给没有 CLI 的人用的方式一样）实测：
   - Codex 给每个会话加写锁（`~/.codex/thread-writer-locks/<会话>.lock` 上的 flock），一个会话同一时刻只归一个进程。
     桌面版自己起一个 app-server 进程，和 lucirund 用的不是同一个；今天 `ps` 里仍是这样。
   - **看**：桌面版占着的会话，别的进程 `thread/read` 照样成功（5 ms）。
   - **接着做**：对桌面版占着的会话 `thread/resume`，立刻报 `already has an active writer`。对 CLI 共享守护进程占着的会话也一样。
   - **反过来**：我们的进程 `resume` 了一个空闲会话之后，第二个进程再 `resume` 同样被拒，桌面版去开它也会是这个结果。
   - **让出**：`thread/unsubscribe` 不放锁（会话仍在 `thread/loaded/list` 里，锁还在）；只有进程退出才放。所以 5.3 第 9 项是必需的：
     lucirund 自己起的 app-server 要在空闲时重启，退出 App 时也自然放手。
   - 面板上标「桌面版正在使用」的办法：每次刷新列表时 `lsof +D ~/.codex/thread-writer-locks` 一次，看每把锁归哪个进程。
   - 对只用桌面版的人，手机上能做的：看共享目录里的所有会话和内容；新开会话；接着做桌面版没开着的会话。
     做不了的：桌面版正开着的会话，手机只能看，不能发消息。
   - 用命令行版 Codex 的人没有这个问题：终端和 lucirund 共用 Codex 的共享守护进程。
   - 还不知道的：桌面版在界面里切换会话时会不会放手（今天它只占着一把 9 月 28 日拿的锁）。
   - 9 月 28 日在桌面版的包里看到一个让它改用共享守护进程的环境变量（`CODEX_APP_SERVER_USE_LOCAL_DAEMON`），没有试过。
     试它要重启 ChatGPT.app，等你点头。能用的话这条限制就可以去掉，但那是一个没有文档的开关，产品不能依赖它。
2. **App 必须开着。** 第一版里 lucirund 是登录后就常驻的系统服务，App 关了、崩了都不影响手机；现在共享跟着 App 进程走。
   手机连不上的情形多了三种：用户退出了 App；App 崩了没人重新打开；没设开机时启动或在系统设置里关了。Mac 睡眠一直存在，和定位无关。
   手机上只看得到「离线」，分不出是哪一种。对策：退出确认；崩溃后由系统重启（第 6 节）；首次使用默认开机启动；
   手机端把「离线」说成「Mac 可能在睡眠，或 LuciControl 没有运行」；设置页可以加「接电源时共享期间不睡眠」。
   还有一条：只用桌面版的人，退出 App 会结束 lucirund 自己起的 Codex 进程，手机发起的、正在跑的回合会被打断。
3. **系统授权框会卡住回合。** macOS 对桌面、文稿、下载、iCloud 云盘、外接盘这些位置按 App 授权，第一次访问时弹框，
   弹框期间那次文件操作一直等着，直到有人点。Codex 桌面版的用户给 ChatGPT.app 授过的权不算数：LuciControl 拉起的 Codex 是另一条进程链，
   弹框写的是 LuciControl。人在电脑前只是多点一次「允许」；人不在时（这正是远程的场景）Codex 一碰这种目录，命令就卡住，
   手机上看到回合一直转，直到回到电脑前点掉。第 6 节的做法能挡住添加目录时的那一次，挡不住 Codex 去访问共享目录之外的地方。
   彻底的办法是「完全磁盘访问」，要用户去系统设置手动开，不建议默认要求，体检页里提示即可。
   只用 Codex CLI 的人基本没这个问题：他们的 Codex 共享进程通常由终端启动，终端早就有权限。
4. **状态的准确度有边界。** 在 Codex 桌面版里跑的线程，lucirund 看不到它的实时状态，面板上会显示空闲。
   只有 lucirund 连着的那个 app-server 里的线程是实时的。
5. **线程列表只有最近 100 条**，更早的会话不会出现在面板里。
6. **RemoteWire 是路径依赖**，两个仓库要并排放。以后可以把它拆成独立仓库。
7. **令牌到期。** 这台 Mac 的令牌会自动续期。别的机器上如果还是开发密钥签的旧令牌，2026-10-26 过期，到期前要重新配对。
   设置页会显示到期日，续期失败时图标变暗并提示重新配对。
8. **阶段 0 已验证的两点**（2026-09-30）：父进程被 `SIGKILL` 之后，读着标准输入的子进程立刻收到 EOF（2 秒内退出）；
   launchd 的 `KeepAlive: {SuccessfulExit: false}` 只在非零退出后重启，正常退出后不再拉起（临时 LaunchAgent 实测，已删）。
   **子进程不被节流**（2026-09-30，一个带子进程的菜单栏测试 App 挂了 4.5 小时，子进程每 20 秒连一次中继：802 次，
   间隔最长 23 秒，没有一次超过 25 秒，全部 200；旁边不在 App 下面的对照组一样）。
   **还没验证的两点**：拖放到状态栏按钮在 macOS 27 上的行为（代码已写，等实际拖一次）；受保护目录的授权框是否如预期挂在 LuciControl 名下（阶段 3）。
